# Relationship memory fading

Workstream 6 implementation, 2026-10-15. Automated verification is separate from live acceptance. No deployment, configuration activation, or new decay default is part of this change.

New relationship notes copy individual eligible member source statements, without a model-generated synthesis or an automatic expiry. Keeping each source separate prevents a new interest from refreshing every older observation. Episode sources are retained as historical events; other observations are conservatively treated as transient. Neither category proves a current preference, personality trait, relationship strength, teasing consent, or a shared experience absent from the source. Context labels them as past evidence and includes its timestamp. Ordinary source retention and access rules remain authoritative.

With the existing fading module enabled, transient retrieval weight is `2 ** (-elapsedDays / halfLifeDays)`, multiplied by lexical relevance. Within relationship recall, a note supported by a single episode keeps its weight. Legacy notes that combine multiple sources are conservatively treated as transient. The existing fading of minor episodes in ordinary memory recall is unchanged. The existing half-life configuration is the only tuning control; its existing 30-day default and disabled-by-default activation are unchanged. With a 30-day half-life, day 89/90/91 weights are about 0.128/0.125/0.122, without removal at any boundary. No new live decay value has been selected: compare relevance and intrusive callbacks in replay and obtain human acceptance before enabling or retuning the module.

Age comes from the latest eligible human provenance timestamp for each supporting record, never from the impression's write/read time. For legacy multi-source summaries use the earliest of those evidence timestamps, so one recent source cannot refresh the whole summary. Consolidation sources without original human timestamps cannot supply freshness. Module summaries cannot support other relationship notes. Reads validate source identity, revision, provenance IDs, audience, isolation, channel memory mode and source expiry on every use. Invalid notes are excluded immediately; physical storage cleanup is independent.

## Bounded legacy migration

The former writer did not persist an expiry reason. The compatibility rule is intentionally limited to its complete recognizable shape: active current member impressions owned by `relationships`, source `consolidation`, topic `character.relationships`, slot `relationship.` plus twelve lowercase hexadecimal characters, nonempty same-member dependency/source-ID metadata, no new `relationshipVersion`, and an expiry exactly 1–365 integral days after `updatedAt`. This covers the former configurable policy, including 90 days. Only that record's expiry is cleared. Source expiries are never changed. This is a bounded inference, not proof of an expiry reason; an independently assigned expiry that exactly imitates that legacy shape cannot be distinguished. Review that rule against deployment data before rollout. Records that do not match every condition retain their expiry.

Both database repositories apply this idempotent rule before module cleanup; relationship reads also apply it before querying eligible rows. Conditional updates avoid overwriting concurrent revisions or expiry changes. A retained row whose sources are unavailable is still ineligible. Already deleted notes are not restored: normal source-based reconstruction and forgetting checks are required. Inactive/superseded versions still use the separate history cleanup duration (existing default 90 days); an independent expiry can remove them sooner. Ordinary member facts are untouched.

`relationships.retentionDays` remains accepted for configuration compatibility but has no runtime expiry effect. The ordinary memory screen now explains impressions and history. `memory.advanced` contains the existing fading half-life and old-version cleanup controls; the half-life control moves from character settings to advanced memory settings, and the impression-expiry control is removed. Changing the half-life does not activate fading.
