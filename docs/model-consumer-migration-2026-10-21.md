# Model-consumer migration inventory

The machine-readable [consumer inventory](model-consumer-inventory-2026-10-21.json) is checked with the TypeScript AST and type checker. It records capability references, including optional methods and bound callbacks, outside the concrete transport implementations. Typed chat-reply methods are distinguished from Discord interaction replies. Adding a consumer requires updating the reviewed inventory and documenting its source authority here. Removing an old path also requires updating the inventory so dead compatibility entries cannot silently remain.

This is a drift detector and migration inventory, **not** universal gateway enforcement. A reviewed legacy entry is still a gap. It does not sandbox arbitrary new networking or discover every dynamically constructed method name. Concrete OpenAI/Gemini/compatible transports remain the leaf serialization owners; their per-attempt hooks have separate transport tests.

| Consumers | Current authority and remaining migration |
| --- | --- |
| `guarded-chat-turn`, contextual `character-decision`, guarded reply/attribution repair in `chat-conversation-service` | Registered text lease, fresh protected sources and final effect permits. Public native search has an explicit provider-managed trust boundary and separate lineage. Other rich sources remain excluded. |
| `background-model-gateway` | Registered background snapshots; input serialization owned by the gateway; fresh source/member/scope checks and checks inside all three providers' summary/extraction retries. Persisted derived claims and downstream memory processing are not covered by this claim. |
| `channel-summary-scheduler` | Extraction references are capability checks for enqueueing; direct summary/extraction invocation moved to the gateway. Memory ingest, relationship ingest and character-consolidation callbacks need the remaining derived-data migration. |
| Legacy operations in `chat-conversation-service` | Dropped-session consolidation, persona drift, overflow summaries and live extraction still accept legacy representations. Their existing eligibility/forgetting checks are not registered universal source authorization. |
| `character-runtime`, `character-modules/voice` | Utility text generation, consolidation, evaluation/probes and legacy voice repair remain independent consumers. Guarded turns exclude learned state and bypass legacy module contributions/postprocessing. Migrate source/purpose/audience provenance before enabling them in guarded context. |
| `memory-engine` | Query embeddings, fact embeddings and conflict classification remain independent. Existing audience/isolation and forgetting logic stays active; it does not replace current source authorization for every statement sent externally. Derived record provenance and mutation-boundary checks are required before safe expanded recall. |
| `user-memory-selector`, `guild-memory-selector`, `example-exchange-selector`, `persona-lore-selector`, `embedding-batch` | External embedding inputs require explicit source/configuration authority. Existing source relevance selection is not the universal guard. Authored configuration and real-chat-derived examples must remain distinct. |
| `caching-embeddings-client` | Delegates external calls and caches vectors. It grants no source authority; invalidation and purpose-scoped keys must follow the owning context. |
| `persona-bundle-compiler` | Processes administrator configuration; classification/embedding ownership must migrate as approved configuration, without assuming embedded real-member facts or chat examples are unrestricted. |
| `generate-self-image-tool` | Existing tool action authorization remains. Prompt/reference-image provenance and provider calls still need the guarded source gateway; excluded from guarded turns. |
| `customize-command` | User-initiated preference analysis with existing command/access controls. Still needs the common explicit-configuration purpose boundary and scope/invalidation integration; it is not a source of unrestricted personal facts. |
| `bootstrap/dependencies` | Composition and bound capability injection, not independent chat authorization. Keep transport construction confined to composition/transport modules; migrate remaining application consumers instead of treating wiring as proof. |
| Replay scripts | Synthetic evaluation consumers. They may exercise registered synthetic leases but cannot authorize real Discord data. Their presence is intentional; they are not production-source migration evidence. |

The conversation-boundary architecture suite additionally restricts imports of the background gateway and context lease to their intended application owner. The consumer inventory catches ordinary new access sites even if a method is saved or bound before invocation. Neither test substitutes for source-specific payload, revocation and persistence tests.

Next substantive migration: persistent claim/source manifests for summary and personal/relational memory, followed by authorization before memory ranking/embedding/conflict processing and recall. Do not re-enable those sources by marking all legacy records eligible or by accepting a model-supplied provenance field.
